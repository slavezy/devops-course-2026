## 1. Почему нельзя коммитить напрямую в main?

Git это позволяет, но в командном процессе прямой коммит может обойти ревью и проверки. Обычно задачу выполняют в отдельной ветке и включают в основную после проверки. Правила определяет команда; в отдельных шагах учебной методички прямой push в main указан явно.

## 2. Шаги GitHub Flow

Создать ветку от актуальной основной ветки, внести изменения и коммиты, отправить ветку, открыть Pull Request, получить ревью, исправить замечания, после одобрения выполнить слияние и удалить завершённую ветку.

## 3. Чем Pull Request отличается от merge?

Merge - операция объединения истории. Pull Request - предложение включить изменения с описанием, обсуждением, ревью и результатами проверок. PR может завершиться merge, squash merge или другим разрешённым способом интеграции.

## 4. Что такое Code Review?

Проверка изменений другим участником до их принятия. Ревью помогает найти ошибки, уточнить требования и сделать решение понятнее. Полезный комментарий указывает конкретное место, проблему и возможное улучшение.

Источник для вопросов 1-4: [GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow).

## 5. Главное отличие Git и SVN

Git - распределённая система: обычный клон содержит историю и поддерживает локальные коммиты. SVN - централизованная: рабочая копия обращается к репозиторию для создания ревизии. Уточнения о ветках и работе без интернета приведены в [svn_comparison.md](../svn_comparison.md).

## 6. Что означает feat:?

Тип изменения, обозначающий новую функциональность, в соглашении Conventional Commits. Общий формат: `type(scope): description`, где scope необязателен. В учебном задании `feat: add hobby project description` используется для добавления описания проекта.

Источник: [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/).

## 7. Как впервые отправить локальную ветку?

```bash
git push -u origin feature/hobby-project
```

Опция `-u` связывает локальную ветку с удалённой; дальнейшие отправки из этой ветки можно выполнять командой `git push`.

## 8. Зачем уметь работать с Git в терминале?

Команды позволяют точно задавать действия, повторять их в скриптах и работать по SSH на сервере без графического интерфейса. IDE удобна для просмотра изменений, но знание команд помогает понимать её операции и разбирать ошибки.

## Подготовка к занятию 3: когда merge, а когда rebase?

Merge подходит для объединения параллельной работы, когда важно сохранить существующие коммиты и структуру ветвления. Rebase подходит для подготовки собственной неопубликованной ветки: переноса на новую базу или очистки истории. Rebase создаёт новые версии коммитов, поэтому опубликованную историю, используемую коллегами, нельзя переписывать без согласования.

Пример: в локальной ветке исправить сообщения и объединить два небольших коммита через interactive rebase; затем предложить проверенные изменения через PR. Условия этой практической требуют завершить PR способом Squash and merge.

Источник: [документация git rebase](https://git-scm.com/docs/git-rebase).
