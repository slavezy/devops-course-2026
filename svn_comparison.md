# Сравнение Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN - «дорогое»?

В Git ветка - небольшая ссылка на коммит. Создание локальной ветки не требует копирования всего проекта или обращения к серверу.

Формулировка вопроса про SVN упрощена: серверная операция `svn copy` тоже использует дешёвые копии и не дублирует все данные. Ветка SVN представлена путём в центральном репозитории; её создание на сервере требует доступа к нему. Поэтому главное отличие - модель работы и зависимость от центрального хранилища, а не обязательное полное копирование файлов при каждом ветвлении.

Источник: [Version Control with Subversion: Using Branches, Cheap Copies](https://svnbook.red-bean.com/en/1.8/svn.branchmerge.using.html).

## 2. Можно ли в SVN сделать коммит без интернета?

Коммит требует доступа к центральному репозиторию. Если он находится на недоступном интернет-сервере, закоммитить нельзя: изменения останутся в рабочей копии. Но сам интернет не обязателен - репозиторий может быть доступен по локальной сети или через `file:///` на этом же компьютере. В Git локальный коммит не требует связи с удалённым сервером; публикация происходит отдельно через `push`.

Источник: [Version Control with Subversion: репозитории и рабочие копии](https://svnbook.red-bean.com/en/1.7/svn.basic.in-action.html).

## 3. Когда SVN может быть предпочтительнее Git?

- В существующем проекте с работающими SVN-инструментами, когда переход на другую систему не оправдывает затрат.
- При работе с плохо сливаемыми бинарными файлами, когда команда использует блокировку, чтобы один файл одновременно редактировал один человек.
- В процессе, где удобнее единое центральное хранилище и общая последовательность номеров ревизий.

Это зависит от требований команды: SVN не ограничен только устаревшими проектами, а Git не всегда является обязательным выбором.

Источник: [Version Control with Subversion: Locking](https://svnbook.red-bean.com/en/1.7/svn.advanced.locking.html).
